## 并查集有什么用

并查集解决的是“哪些元素已经属于同一组”。例如道路不断开通，询问两座城市是否已经连通；朋友关系不断加入，询问两人是否间接属于同一个圈子。每次关系加入可以合并两组，查询时不必重新遍历整张图。

它保存的是分组结果，不保存城市间的具体路线，也不能直接回答最短路。普通模板适用于合并而不拆组；如果要删除道路，原来的连通组可能裂开，就不是一次简单改父指针能解决的。

## 先用五个元素看懂父指针

一开始 $1\ldots5$ 各自成组，$\mathrm{parent}[i]=i$；“父亲是自己”表示根。合并 1、2 后，让 2 的根指向 1；再合并 1、3，1 成为三元素集合的代表。合并 4、5 后，5 指向 4。

此时查询 2 和 5 是否同组，不能比较 $\mathrm{parent}[2]$ 与 $\mathrm{parent}[5]$ 就结束，而是分别沿父链找最终根：2→1，5→4，所以不同组。

再合并这两组，找到根 1 和 4。按大小把两元素集合的根 4 挂到三元素集合的根 1 下，$\mathrm{group\_size}[1]=5$。5 的父亲可能仍是 4，但沿 5→4→1 可以找到代表 1，因此五个元素已经同组。

find_root(5) 的路径压缩把 $\mathrm{parent}[5]$ 改为 1，下一次从 5 可以直接到根。**它改变了查找路线，没有改变分组。** 所以父指针不必实时让每个元素都直接连根，只需保证根最终一致。

## 静态数组和函数分别保存什么

| 名称 | 含义 |
|---|---|
| $\mathrm{parent}[x]$ | x 当前指向的父节点，根指向自己 |
| $\mathrm{group\_size}[\mathrm{root}]$ | 根对应集合的元素数量，非根位置不保证有意义 |
| init(n) | 为每个元素创建独立集合 |
| find_root(x) | 找根，并压缩经过的父链 |
| $\mathrm{unite}(x,y)$ | 先找两个根，再按集合大小连接 |

本模板容量 $N=200005$，支持 $n\le 200000$；编号必须在 $1\ldots n$。多组数据重新调用 init，不保留上一组父指针。

## 核心操作与优化说明

初始化 $\mathrm{parent}[x]=x$；find 沿父链找到根；合并必须连接两个根。路径压缩把查找路径连到根，按大小合并把小集合根挂到大集合根，并更新新根 size。

size 是集合元素数量，不是树高；rank 是辅助秩，路径压缩后不再等于实际高度。两种合并策略都有效，但不应混用解释。仅有 $\mathrm{parent}[\mathrm{find}(x)]=\mathrm{find}(y)$ 省略了按大小/秩合并，不能直接宣称与两种优化相同的复杂度保证。

## 完整程序：合并与连通查询

测试：[洛谷 P3367 — 并查集](https://www.luogu.com.cn/problem/P3367)。输入 n、q，操作 1 x y 合并，2 x y 输出 Y/N，元素编号 $1\ldots n$。

```cpp
#include <bits/stdc++.h>
using namespace std;

const int N = 200005;
int parent[N];
int group_size[N];

void init(int n)
{
    for (int i = 1; i <= n; i++)
    {
        parent[i] = i;
        group_size[i] = 1;
    }
}

int find_root(int x)
{
    if (parent[x] == x)
    {
        return x;
    }
    parent[x] = find_root(parent[x]);
    return parent[x];
}

bool unite(int x, int y)
{
    x = find_root(x);
    y = find_root(y);
    if (x == y)
    {
        return false;
    }
    if (group_size[x] < group_size[y])
    {
        swap(x, y);
    }
    parent[y] = x;
    group_size[x] += group_size[y];
    return true;
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    init(n);
    while (q--)
    {
        int op, x, y;
        cin >> op >> x >> y;
        if (op == 1)
        {
            unite(x, y);
        }
        else if (find_root(x) == find_root(y))
            cout << "Y\n";
        else
        {
            cout << "N\n";
        }
    }
}
```

正确性：每棵父树表示一个集合，只连不同根不会形成父指针环；路径压缩不改变根，所以集合划分不变。初始化 $O(n)$，空间 $O(n)$，两种优化后操作序列的单次摊还 $O(\alpha (n))$，实际很慢增长；不是每次严格 $O(1)$。

## 应用与边界

动态增加无向边的连通性、连通块大小、Kruskal 判环。成功合并时连通块数减 1，重复合并与 $x=y$ 不变。只有根上的 size 有效，查询应读 $\mathrm{group\_size}[\mathrm{find\_root}(x)]$。

普通并查集不支持删边、拆集合或输出两点实际路径；父指针不是原图路径。带权、可回滚并查集是后续扩展，回滚通常不能直接保留任意路径压缩。

## 扩展选读：复杂度为什么很小

**可直接证明的界：** 仅按大小合并、不路径压缩时，一个节点深度增加，必因它所在集合挂到至少同样大的集合；其集合规模至少翻倍。规模 $\le n$，深度最多 $\log_2 n$，因此 find 最坏 $O(\log n)$。路径压缩又缩短了路径，不破坏集合含义。

**更强的摊还定理：** 同时使用按秩/大小合并和路径压缩，m 次操作总界可写为 $O((n+m)\alpha (n))$。严格证明需要将父链增长按快速增长的秩层级分组，并对整个操作序列计费；不能从“集合翻倍”直接推出 $\alpha (n)$。本篇给出可验证的 $O(\log n)$ 证明和更强定理的准确含义，完整反阿克曼分析留作高级选读，不伪装成单次常数界。

## 扩展选读：强摊还界的引用范围

逆阿克曼函数来自快速增长层级的反向计数。一种约定为 $A_0(j)=j+1$、$A_{i+1}(j)=A_i^{(j+1)}(j)$（上标表示重复复合），再定义 $\alpha(n)=\min\{i:A_i(1)\ge n\}$。文献的起始值或双参数定义可能不同，但不影响这里的渐近摊还结论。

证明路线是给节点一个随合并增长的秩，再按快速增长的秩阈值分层。路径压缩访问父边时，区分跨越层级与仍在同一层级的访问，对整个操作序列计费；压缩后跳得更远会消耗对应的层内额度。需要证明秩的单调性、每层额度及所有节点的总计费，不能只数一次 find 的长度。

本篇**引用**“按秩/大小合并加路径压缩”的逆阿克曼摊还定理，没有把上述路线当成完整严格证明。可从 [Princeton Union–Find 课程资料](https://www.cs.princeton.edu/courses/archive/spring21/cos226/lectures/15UnionFind.pdf) 的 Union–Find 讲义继续阅读。实现按大小合并；大小的对数层级提供与按秩分析对应的规模增长控制。只要求确定最坏单次界时，前面的大小倍增证明已给 O(log n)；要求强总界时才需要这个定理。

## ABC451F Make Bipartite 3

[官方题面](https://atcoder.jp/contests/abc451/tasks/abc451_f)

从空图开始逐次加无向边，每次判断能否二染色，并在可行时求最少黑点数。N,Q≤2×10⁵。

> [!tip]- 提示一
> 每个连通分量整体翻转颜色仍合法，它对答案只贡献两侧人数的较小者。

> [!tip]- 提示二
> 让 d[x] 表示 x 与并查集根的颜色异或；合并两根时推导必须附带的异或值。
>
> 复习：[[03数据结构/07-并查集]]。

> [!example]- 详细题解
> **建模与源码主线。** `find` 压缩路径时把旧父亲的 d 异或进 d[x]。合并 u,v 的根 lf,rf，令 rf 指向 lf，关系为 `reld=1^d[u]^d[v]`。先从 `totalmin` 减去两个旧分量的较小侧人数，再按 reld 决定是否交换 rf 的 cnt0/cnt1 后累加，最后加回新分量贡献。同根且 d[u]=d[v] 就产生冲突。
>
> **正确性与适用条件。** 每条边要求 color[u] xor color[v]=1，所设根关系恰好维持这个等式。连通二分图的颜色方案只有整体翻转两种，故每个分量独立选较小侧染黑即可最优；加边产生奇环后，后续加边不能消除矛盾，`possible=false` 可永久保留。
>
> **手算与边界。** 依次加入 1−2、2−3、3−4，两个颜色类的人数为 (1,1)、(2,1)、(2,2)，答案 1、1、2；再加 1−3，两端关系相同，输出 −1。
>
> **实际复杂度与实现。** 当前实现只有路径压缩，没有按秩合并，不直接宣称 O(α(N))；采用保守摊还 O((N+Q) log N) 分析，空间 O(N)，build 还会初始化固定 200000 个位置。递归 find 的瞬时深度也应关注；按大小合并可取得标准并查集界。

## ABC447E Divide Graph

[官方题面](https://atcoder.jp/contests/abc447/tasks/abc447_e)

连通图第i条边代价2^i，删边后恰有两个连通分量，求最小真实代价模998244353。

> [!tip]- 提示一
> 某条高位边的代价超过全部低位边之和，应尽量保留高位边。

> [!tip]- 提示二
> 从高编号往低编号合并端点，直到只剩两个分量，剩下跨分量边必须删。
>
> 复习：[[03数据结构/07-并查集]]。

> [!example]- 详细题解
> **建模与源码主线。** 源码ltk初始化N，逆序边同根直接保留；不同根且ltk>2时合并并减ltk，否则把该边留作删除。最后遍历vis仍为真的边，累加power2(i)的模值。它比较的是二进制权值的高位优先次序，没有按模后的大小选边。
>
> **正确性与适用条件。** 已决定保留的高位边必须处于同一分量。只要分量超过2，当前边连接不同分量仍可保留，原图连通保证后续可继续连到2；若已剩2个，再保留跨边就会合成1个，只能删除。最高不同决策位支配全部低位，故每次优先保留给出全局最小删除代价。
>
> **手算与边界。** 三角形边编号1:(1,2)、2:(2,3)、3:(1,3)，先保留边3得到两分量，边2、1都跨分量需删，总代价4+2=6；删除最贵边再做普通最小生成树不对应目标。
>
> **实际复杂度与实现。** 源码每条删除边单独快速幂，额外O(M log M)；仅路径压缩、不按秩合并，保守总时间O((N+M) log N+M log M)，空间O(N+M)。预处理2的幂可省快速幂重复开销。
