## 根据操作选择结构

| 需求 | 候选 | 不要混淆 |
|---|---|---|
| 后进先出/先进先出 | 栈/队列 | 访问前检查 empty |
| 已知节点频繁改相邻关系 | 链表 | 查找第 k 个节点并非 $O(1)$ |
| 动态集合取最值 | 堆 | 不提供完整有序遍历 |
| 最近更大位置/窗口最值 | 单调栈/队列 | 大量弹出仍需摊还分析 |
| 有序查前驱后继 | set/multiset/map | k 很大时线性移动迭代器慢 |
| 只合并不拆分的连通集合 | 并查集 | 父指针不是图中路径 |
| 单点加、区间和 | 树状数组 | 内部下标不能为 0 |
| 区间加、区间和 | 线段树、两 BIT、分块 | 不能照搬离线差分后即时查询 |
| 静态区间和/最值 | [[01-前缀和]]、[[07-ST表与静态区间查询]] | 不必为静态问题先上动态树 |

## 阅读与验证约定

代码统一使用四空格缩进、左大括号另起一行，每条语句独占一行，不把多个操作压在一行；for 的循环头仍按正常语法书写。能用静态数组和普通函数实现的模板不封装自定义类，静态容量由各篇明确说明。lambda 仅用于 sort 比较或简单判断，主要操作、扫描与查询写成命名函数。

正文先读原理、完整程序、应用和边界。复杂度结论在正文保留，详细推导统一放在各篇最后的“扩展选读”，尤其并查集的摊还分析与线段树的节点访问界。

每个程序使用一个明确输入契约；教学小程序不自动代表已通过平台评测。先跑样例和边界，再用独立朴素结构小规模随机核对。不要只比较代码长短：数值范围、更新类型、静态/动态和复杂度保证同样重要。

## 评分尺度

这里的分数面向本项目的算法竞赛学习路线，是主观学习建议，不是平台评级，也不是题目出现频率统计。两个维度都为 1–10，分数越大表示越难或越重要。

- **难度**：综合理解、实现、边界处理和基本正确性证明。1–3 为基础操作，4–6 需掌握状态或不变量，7–8 通常涉及多种机制，9–10 为理论或高级专题。正文算法评分不把篇末复杂度证明全部算进去。
- **重要程度**：综合基础性、应用覆盖、后续知识依赖和练习复用。9–10 建议优先熟练，7–8 是主线内容，5–6 按题目需要学习，1–4 可后置选读。高难度不自动代表高重要程度。
- 同一算法在不同模块出现时采用一致尺度；题解里组合应用可比单个模板更难。标为“后续扩展”的条目仅说明位置，不表示本篇已有完整实现。

## 统一代码风格

四空格缩进，左大括号另起一行，每条语句单独一行，不压行。for 循环头保留正常语法。能用静态数组与普通函数的主模板不封装自定义类；lambda 只用于 sort 比较或简单判断。标准库堆、有序容器和哈希容器保留其接口，避免为去掉容器而改变算法复杂度。

空间复杂度描述有效数据规模，静态数组实际分配量按声明容量计算。
