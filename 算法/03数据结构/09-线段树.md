## 线段树有什么用

假设有一排数，需要反复做两件事：给某一段所有数加一个值，再询问某一段的总和。例如工资批量调整后查询某组人的工资总额，或给连续区域增加数量后统计局部数量。查询与更新交错发生，后一次询问必须看到前面所有修改。

普通数组可以做到，但一次长区间修改或查询都可能遍历 n 个数；n 和操作次数都很大时会很慢。前缀和适合数组不变的查询，修改一个数会影响后面许多前缀；差分擅长先记录所有修改、最后恢复，却不能直接快速回答每次修改之后的区间和。

线段树把数组拆成大小不同的区间，保存这些区间的统计。当目标区间恰好覆盖某个节点时，直接使用这份统计，不再逐个访问元素。本篇解决“区间加、区间和”；不是所有区间问题都能直接套本模板。

## 一、节点不是一个元素，而是一段区间

用数组 [1,2,3,4] 举例，根表示整个 [1,4]，然后把区间不断分成两半，直到单个位置：

```text
                    u=1 [1,4] 和=10
                   /                \
          u=2 [1,2] 和=3        u=3 [3,4] 和=7
             /       \             /       \
      u=4 [1,1]   u=5 [2,2]  u=6 [3,3]  u=7 [4,4]
          和=1        和=2       和=3        和=4
```

这里 a[3]=3 是原数组第 3 个数；tree[3]=7 则是树的第 3 号节点维护的 [3,4] 的和。**树节点编号与原数组位置是两套编号，不能混为一谈。**

本实现按 u*2、u*2+1 编号左右孩子。区间 [l,r] 的中点 mid 把它分为 [l,mid] 与 [mid+1,r]；两个孩子无重叠且覆盖父区间，所以父和等于左右和相加。

## 二、建树与向上合并做了什么

build(u,l,r) 的任务是建立“u 号节点负责 [l,r]”这件事。如果 l=r，区间只有一个数，tree[u]=a[l]；否则先分别建立左右孩子，再把两者之和保存到父节点。

push_up(u) 就是这次相加。它不是把值“向父亲发送”，而是**用 u 的两个孩子重新计算 u 本身**。函数名容易误导，记住它的实际职责即可。

例如原数组第 3 项从 3 增加到 8，对应叶子 u=6 的和改为 8；其父 u=3 从 7 变为 12，根从 10 变为 15。只需重算这条路径，不必重算与修改无关的左半区间。

## 三、查询区间为什么只走部分分支

以查询 [2,3] 为例：根 [1,4] 不能整体拿走，因为它还包含位置 1 和 4。进入左孩子 [1,2] 时只访问位置 2，得到 2；进入右孩子 [3,4] 时只访问位置 3，得到 3；相加得到 5。

递归有两类情况：

1. 当前区间 [l,r] 完全包含在查询目标 [L,R] 内：直接返回 tree[u]。
2. 只有部分重合：看目标是否跨过 mid，按需进入左边、右边或两边，再合并返回值。

参数 u、l、r 描述**当前树节点**，L、R 描述**这一整次操作的固定目标**。进入子节点时只改变前三个参数，不能随意改变目标区间。

## 四、整段加法为什么需要懒标记

给 [1,4] 全部加 5，真实数组应为 [6,7,8,9]，总和从 10 变为 30。既然根负责四个数，就可以立即令 tree[1]+=5*4，而不是立刻找到四个叶子各加 5。

但孩子还保存旧值，不能忘了以后也要更新它们。因此 lazy[1]+=5，记录“这个节点的区间已经整体加了 5，但这项影响尚未传给孩子”。这就是懒标记。

**tree 已经计入修改，lazy 是向孩子传递的欠账，不是尚未计入当前节点的修改。** 只改 lazy 不改 tree，会让整段查询直接读出旧总和；改完 tree 后下放时再加到父 tree，又会重复计入。

apply_add(u,l,r,value) 同时完成这两件事：当前和增加 value*区间长度，当前待传标记增加 value。两次加 5、加 2 可合成为加 7，所以这个模板的标记用加法累计。

## 五、下放标记：用一次查询追踪全过程

继续上一例，根 tree[1]=30、lazy[1]=5，左右孩子仍为 3、7。现在查询 [2,3]，不能直接使用孩子旧统计，必须先 push_down：

| 步骤 | 节点统计如何变化 | 标记如何变化 |
|---|---|---|
| 根传给左右孩子 | 左和 3→13，右和 7→17 | 左右 lazy 各加 5，根 lazy 清为 0 |
| 左孩子传给位置 1、2 | 叶子和变为 6、7 | 叶子收到 5，左孩子 lazy 清为 0 |
| 右孩子传给位置 3、4 | 叶子和变为 8、9 | 叶子收到 5，右孩子 lazy 清为 0 |
| 返回查询值 | 位置 2 与位置 3 的和为 7+8=15 | 根总和仍为 30，不再额外加值 |

为什么根的 lazy 要清零？它的欠账已经交给孩子负责，如果保留，下一次局部访问会把同一个 5 再传一遍。

孩子收到标记后可以继续暂存，直到确实需要访问更深层。叶子没有孩子，不需要继续下放。**存在祖先欠账时，某个后代的 tree 可能还不是当前真实值；查询沿路下放后，所取统计才包含祖先修改。**

## 六、更新区间时的顺序

update 的完整覆盖情况直接 apply_add 并返回。部分覆盖则先 push_down，把之前欠给孩子的修改补齐，再进入需要更新的孩子，最后 push_up 重算当前区间和。

仍以 [6,7,8,9] 为例，给 [3,4] 加 -2：右孩子和从 17 变为 13，lazy[3] 记 -2；左孩子和仍 13，根重新计算为 26。没有必要立即把右侧两个叶子改成 6、7，因为右孩子已知道整段最新总和。

查询只下放、汇总结果，不会改变真实数组值。下放前后左右和之和与父和一致，所以查询不需要额外 push_up；部分更新改变了孩子的真实统计，则必须 push_up。

## 七、先记住每个函数的职责

| 函数 | 用来干什么 |
|---|---|
| build(u,l,r) | 把初始数组统计建立到每个区间节点 |
| push_up(u) | 用左右孩子统计重算当前节点 |
| apply_add(u,l,r,value) | 更新当前节点和，并累计待传加法 |
| push_down(u,l,r) | 把当前待传加法交给两个孩子，再清当前标记 |
| update(...) | 对目标区间加值，部分访问前下放、回来后上合 |
| query(...) | 取目标区间和，部分访问前下放 |

## 完整程序：区间加与区间和

测试：[洛谷 P3372 — 线段树 1](https://www.luogu.com.cn/problem/P3372)。输入 n、q、数组；1 l r value 给闭区间加值，2 l r 查询区间和。1≤n≤100000，本模板静态容量 N=100005、树数组 4*N，所有中间和与乘积须在 long long 范围内。

```cpp
#include <bits/stdc++.h>
using namespace std;

const int N = 100005;
long long a[N];
long long tree[N * 4];
long long lazy[N * 4];

void push_up(int u)
{
    tree[u] = tree[u * 2] + tree[u * 2 + 1];
}

void build(int u, int l, int r)
{
    if (l == r)
    {
        tree[u] = a[l];
        return;
    }
    int mid = l + (r - l) / 2;
    build(u * 2, l, mid);
    build(u * 2 + 1, mid + 1, r);
    push_up(u);
}

void apply_add(int u, int l, int r, long long value)
{
    tree[u] += value * (r - l + 1);
    lazy[u] += value;
}

void push_down(int u, int l, int r)
{
    if (l == r || lazy[u] == 0)
        return;
    int mid = l + (r - l) / 2;
    apply_add(u * 2, l, mid, lazy[u]);
    apply_add(u * 2 + 1, mid + 1, r, lazy[u]);
    lazy[u] = 0;
}

void update(int u, int l, int r, int L, int R, long long value)
{
    if (L <= l && r <= R)
    {
        apply_add(u, l, r, value);
        return;
    }
    push_down(u, l, r);
    int mid = l + (r - l) / 2;
    if (L <= mid)
        update(u * 2, l, mid, L, R, value);
    if (R > mid)
        update(u * 2 + 1, mid + 1, r, L, R, value);
    push_up(u);
}

long long query(int u, int l, int r, int L, int R)
{
    if (L <= l && r <= R)
        return tree[u];
    push_down(u, l, r);
    int mid = l + (r - l) / 2;
    long long result = 0;
    if (L <= mid)
        result += query(u * 2, l, mid, L, R);
    if (R > mid)
        result += query(u * 2 + 1, mid + 1, r, L, R);
    return result;
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    for (int i = 1; i <= n; i++)
        cin >> a[i];
    build(1, 1, n);
    while (q--)
    {
        int op, l, r;
        cin >> op >> l >> r;
        if (op == 1)
        {
            long long value;
            cin >> value;
            update(1, 1, n, l, r, value);
        }
        else
            cout << query(1, 1, n, l, r) << '\n';
    }
}
```

## 按这个顺序手算和验证

先建 [1,2,3,4]，查 [2,3] 得 5；整段加 5，查整段得 30；再查 [2,3] 得 15；给 [3,4] 加 -2，查整段得 26。尝试把每次涉及的 u、区间、tree、lazy 列出来，再对照函数执行。

静态数组 a 只作为建树输入，之后不会逐项自动更新；应通过 query 读取当前值，例如单点 query(x,x)。多组数据时需要清空 tree/lazy 并重新建树，本程序仅处理一组。

检查 n=1、n 不是 2 的幂、整段与局部更新交错、重叠、零与负增量。区间输入必须满足 1≤L≤R≤n。

## 哪些变式能直接改

单点修改+区间统计需要能合并左右信息；区间懒更新还需要能直接修改节点统计并正确合成标记。“满足结合律”只解决合并，不保证任意区间更新都能懒处理。

max/min 统计在区间加法下可以直接加 value，但区间和要加 value*长度。赋值标记需单独保存“是否存在赋值”，因为赋值为 0 也是合法修改。先乘后加与先加后乘不同，不能简单把各类标记分别累加。先熟练本模板，再学习新标记，不要直接替换几个符号。

建树 O(n)，单次连续区间加/和 O(log n)，空间 O(n)。结构选择见 [[00-数据结构]]，对拍方法见 [[11-错误解法与边界检查]]。

## 扩展选读：时间与空间证明

**建树：** 每个非叶节点有两个孩子，n 个叶子的实际节点数为 2n-1；每节点计算一次，因此 O(n)。

**数组空间：** 递归编号不紧凑，但补齐到最近 2 的幂 N0=2^ceil(log₂n) 的层布局最多 2N0-1 个位置；N0<2n，所以 4n 容量足够。4n 是方便的编号容量，不是实际节点数。

**一次连续区间操作：** 每层只有包含目标左右边界的至多两个节点还需部分展开，完整包含的节点立即处理并停止；下一层从边界节点展开的孩子数量为常数。高度 O(log n)、节点处理 O(1)，故总 O(log n)。若完整覆盖时仍强制访问所有叶子，就不再有这个界。
