**静态容量：** up[60][200005] 支持 n≤200000、k≤10^18，表元素约占48MB。 增大输入范围前需调整容量并检查内存；多组数据需重置有效状态。

## 解决什么问题

有确定的下一状态 f(x)，需要多次查询走 k 步后的状态。逐步模拟一次查询 O(k)，当 k 很大时不可行。预处理“走 1、2、4、8……步”的结果，把 k 按二进制拆开即可。这里讲函数跳转，树上应用见 [[LCA]]。

## 状态与转移

令 up[b][v] 表示从 v 走 2^b 步的终点。

$$
up[0][v]=f(v),\qquad up[b][v]=up[b-1][up[b-1][v]].
$$

走 2^b 步等于连续走两次 2^(b-1) 步。查询按 k 的置位依次跳转，例如 13=8+4+1。只要跳转规则不变，即使有环、自环也能使用倍增。

## 完整例子：函数图跳转

输入 n、q，接着 n 个下一位置（1-based），再输入 q 行起点 x 与步数 k。输出终点。n≥1，0≤k≤10^18。拓展测试：[AtCoder ABC167 D — Teleporter](https://atcoder.jp/contests/abc167/tasks/abc167_d)。原题只有一次从位置 1 出发的查询，输入为 n、k 和下一位置数组；本模板扩展为多查询，提交时需调整输入。

```cpp
#include <bits/stdc++.h>
using namespace std;
const int N = 200005, LOG = 60;
int up[LOG][N];
int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, q;
    cin >> n >> q;
    for (int v = 0; v < n; v++)
    {
        cin >> up[0][v];
        up[0][v]--;
    }
    for (int b = 1; b < LOG; b++)
        for (int v = 0; v < n; v++)
            up[b][v] = up[b - 1][up[b - 1][v]];
    while (q--)
    {
        int x;
        unsigned long long k;
        cin >> x >> k;
        x--;
        for (int b = 0; b < LOG; b++)
            if ((k >> b) & 1ULL)
                x = up[b][x];
        cout << x + 1 << '\n';
    }
}
```

## 正确性与复杂度

按 b 归纳，表项确为走 2^b 步的结果。查询不变量：x 是从原起点走过已经处理的二进制位之和后的状态。每个置位增加对应步数，处理完即走了 k 步。k=0 时没有跳转，返回起点。

若 L 是覆盖最大步数的位数，预处理 O(nL)，每次查询 O(L)，存储 O(nL)。60 层、n=200000 时仅整型表约 48 MB，还需计入容器开销；步数较小时可以减少层数。不能根据 n 的位数决定层数：状态少也可能查询很大的步数。

## 带路径信息的倍增

若每次从 v 出发的一步代价是 w[v]，令 cost[b][v] 为这段 2^b 步的代价和：

$$
cost[b][v]=cost[b-1][v]+cost[b-1][up[b-1][v]].
$$

查询时先累加原 x 对应段的 cost，再更新 x，不能先跳后取成本。最大值、矩阵乘积等可合并信息也能维护，但必须保证结合律，且非交换操作要保持路径顺序。k 很大时总和可能溢出，应依据题目选择类型或取模。

## 适用边界

- 每个状态必须有唯一下一状态；一般多分支图不能直接用这个表回答所有路径问题。
- 跳转规则修改后，原表通常失效，静态倍增不直接支持动态修改。
- 表里有“无下一位置”哨兵时必须单独处理，避免用 -1 做数组下标。
- 树祖先跳转需要约定根的父亲，距离限制与 LCA 逻辑需在图论中另讲。
