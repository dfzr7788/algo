## 解决什么问题

复杂度描述输入规模增长时，资源消耗如何增长。它用于比较方案和排除明显不可行的解法，不是运行秒数的保证。

## 核心概念

- 时间复杂度：计数主要操作的次数，通常关注最坏情况。
- 空间复杂度：输入存储和额外空间应分开说明，递归栈也占空间。
- 大 O 表示渐近上界，忽略常数和低阶项；多个参数不能随意合并，例如图遍历是 $O(V+E)$。
- 期望复杂度依赖随机性；均摊复杂度描述一串操作的平均成本，两者不能混用。

## 如何计算

### 循环与组合

顺序执行的两段分别为 $O(n)$ 和 $O(n^{2})$，总计 $O(n^{2})$。嵌套循环需要统计内层总执行次数，不能只看有几层。

```cpp
// 总次数 0+1+...+(n-1)，为 O(n²)
for (int i = 0; i < n; ++i)
    for (int j = 0; j < i; ++j)
    { /* O(1) 操作 */
    }

// j 不回退，总推进至多 n 次，总计 O(n)
int j = 0;
for (int i = 0; i < n; ++i)
    while (j < i)
    {
        ++j;
    }
```

第二段虽然嵌套了 while，但 j 在所有轮次中合计只增加 $n-1$ 次（$n\ge 1$）。实际双指针算法见 [[05-双指针与滑动窗口]]。

### 递归

| 递推关系 | 展开方式 | 时间 |
|---|---|---|
| $T(n)=T(n-1)+O(1)$| n 层，每层常数工作 |$O(n)$ |
| $T(n)=T(n/2)+O(1)$| 每层规模减半 |$O(\log n)$ |
| $T(n)=2T(n/2)+O(n)$|$\log n$ 层，每层总工作 $O(n)$|$O(n \log n)$ |
| $T(n)=2T(n-1)+O(1)$| 二叉递归树 |$O(2^{n})$ |

递归深度不等于总调用次数。枚举 n 个元素的全部排列，仅输出结果就需要 $\Omega (n\cdot n!)$ 时间。

### 均摊分析

滑动窗口中，一个元素至多进入一次、离开一次，因此总移动 $O(n)$。`vector::push_back` 偶尔触发 $O(n)$ 扩容，但连续 n 次追加的总搬移量是 $O(n)$，每次追加均摊 $O(1)$。

## 从数据范围反推方案

以下是候选方向，不是固定通过阈值。还要考虑时限、常数、多组数据和内存。

| 规模量级 | 优先评估的方案 |
|---|---|
| $n\le 10$| 排列枚举，注意 $n!$ 和输出规模 |
| $n\approx 20$|$2^{n}$ 子集、搜索剪枝 |
| $n\approx 40$ | 折半枚举；合并成本需另算 |
| $n\approx \text{几千}$|$O(n^{2})$ 可能可行 |
| $n\approx 2\times 10^{5}$|$O(n)$、$O(n \log n)$ |
| 值或答案范围很大 | 对数算法、数学化简，不能按值直接枚举 |

例如 $n=200000$ 时，$n^{2}$ 约为 $4\times 10^{10}$，而 $n \log_2 n$ 约为 $3.5\times 10^{6}$，两者差距很大。

## 数值与空间边界

- 200000 个数各为 $10^{9}$，总和达到 $2\times 10^{14}$，要用 `long long`。
- `long long s = 1LL * a * b;` 在乘法之前提升类型；乘完再赋给长整数无法补救溢出。
- $10^{8}$ 个 4 字节整数约占 400 MB，容器和其他数组还会额外占空间。
- 长链递归可能爆栈，即使时间是 $O(n)$，仍需考虑改用显式栈。
- 多组测试应分析 $\sum n$、$\sum n^{2}$，而不是只看单组上限。

## 完整分析示例

对数组排序后，双指针找两数之和：排序 $O(n \log n)$，指针推进 $O(n)$，整体 $O(n \log n)$。如果额外保存原下标，存储 $O(n)$；不能只报双指针阶段的 $O(n)$。

## CF2185D OutOfMemoryError

[官方题面](https://codeforces.com/contest/2185/problem/D)

数组单点非负增加，任一值超过H时整个数组立刻恢复初始值，输出全部操作后的数组。

> [!tip]- 提示一
> 恢复时不必遍历N个位置，只处理本轮确实改过的位置。

> [!tip]- 提示二
> 同一个位置可以在队列重复出现；从全部操作角度证明总清空代价。
>
> 复习：[[01基础算法与思想/01-复杂度分析与数据范围]]。

> [!example]- 详细题解
> **建模与源码主线。** 源码a保持初始值，sum存本轮增量；每次sum[b]+=c并将b入队。若a[b]+sum[b]>H，清空队列并把每个出队位置sum置0。最终输出a+sum。队列虽可重复存同一位置，重复清零也无影响。
>
> **正确性与适用条件。** 上次恢复后只有被更新的位置可能有非零sum，队列覆盖了它们；清空即可恢复全数组。每次操作只产生一个队列记录，每个记录最多出队一次，故所有恢复循环合计O(M)，不是每次O(N)也不是O(M²)。
>
> **手算与边界。** a=(2,3),H=5，先给第一项+2变4，再给第二项+3触发恢复，两项回到(2,3)，并非仅撤销第二项。若第一项重复更新，队列里的重复编号不会造成错误。
>
> **实际复杂度与实现。** 总时间O(N+M)，空间O(N+M)。sum、a与增加结果用long long；初始a≤H，非负增加保证只检查本次更新位置就能发现越界。

## 牛客141877D 小月的回声

[官方题面](https://ac.nowcoder.com/acm/contest/141877/D)

正整数数组1≤a[i]≤30，统计长度至少3且a[l]a[r]等于内部元素和的区间，N≤2×10⁵。

> [!tip]- 提示一
> 端点乘积最多900，内部正数和持续增大。

> [!tip]- 提示二
> 固定左端累计内部和，一旦超过30a[l]便终止。
>
> 复习：[[01基础算法与思想/01-复杂度分析与数据范围]]。

> [!example]- 详细题解
> **建模与源码主线。** 源码每个l从r=l+2开始，sum每轮加a[r−1]；若sum>a[l]·30就break，否则比较a[l]·a[r]=sum累加ans。全局前缀和数组虽有构造，实际内层用局部sum，并没有做区间二分。
>
> **正确性与适用条件。** 右端最大30，所以超过30a[l]后，无论未来右端取什么都达不到内部和；内部值≥1使和严格增加，停止后不会重新变可行。每个左端至多检查30a[l]+1个候选，不是O(N)个，严格检查r=l+2保证至少一个内部元素。
>
> **手算与边界。** a=(1,2,2,1)，[1,3]有1×2=2，[2,4]有2×1=2，共2。若值域没有30上界，提前停止与复杂度保证都不成立。
>
> **实际复杂度与实现。** 时间O(NV²)，V=30，最坏约900N次，不能简单称为常数极小的线性；空间O(N)，源码额外前缀数组可省。ans用long long，局部sum不超过阈值太多，int足够。
