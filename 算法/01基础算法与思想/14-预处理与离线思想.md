**静态容量：** 数组与查询容量 $N=200005$，要求 n、$q\le 200000$。 增大输入范围前需调整容量并检查内存；多组数据需重置有效状态。

## 预处理与离线的区别

预处理是在查询前先计算可复用信息，比如前缀和、阶乘、倍增表。离线是在知道全部查询后，调整处理顺序以共享工作。预处理不要求查询可重排，离线则必须保证换顺序不会改变题意。

| 情况 | 方法 | 限制 |
|---|---|---|
| 静态区间和 | 一次前缀和，逐个查询 | 数组修改后原前缀通常失效 |
| 多次确定性跳转 | [[11-倍增思想]] | 跳转规则保持不变 |
| 静态阈值查询 | 查询排序，逐步加入元素 | 各查询互相独立 |
| 后一个查询由前一个答案解密 | 通常需按原顺序在线处理 | 不能先排序未知查询 |

要计算“预处理+全部查询”的总成本，并估算额外存储。仅有一次查询时，昂贵预处理可能没有收益。

## 完整例子：不超过阈值的元素个数

输入 n、q，接着 n 个整数和 q 个阈值 x，按原查询顺序输出数组中 $\le x$ 的元素数量。n、$q\le 200000$，可为 0，整数在 `long long` 范围内。

每个查询扫描数组：$O(nq)$。数组排序后每个查询 `upper_bound`：$O(n \log n+q \log n)$，可在线处理阈值。离线则同时排序查询，维护一个只前进的指针。

```cpp
#include <bits/stdc++.h>
using namespace std;
const int N = 200005;
long long a[N];
pair<long long, int> queries[N];
int answer[N];
int main()
{
    int n, q;
    cin >> n >> q;
    for (int i = 0; i < n; i++)
        cin >> a[i];
    for (int i = 0; i < q; i++)
    {
        cin >> queries[i].first;
        queries[i].second = i;
    }
    sort(a, a + n);
    sort(queries, queries + q);
    int p = 0;
    for (int i = 0; i < q; i++)
    {
        long long x = queries[i].first;
        int id = queries[i].second;
        while (p < n && a[p] <= x)
            p++;
        answer[id] = p;
    }
    for (int i = 0; i < q; i++)
        cout << answer[i] << '\n';
}
```

不变量：处理阈值 x 后，a 中前 p 个元素恰好 $\le x$。阈值不下降，已经满足的元素不需退出；每个数组元素最多推进一次。id 保存原顺序，排序仅改变计算顺序。

例：$a=[3,1,3]$，查询 [3,0,1]，输出 [3,0,1]。排序后不能直接按处理顺序输出。重复值要全部推进，重复查询可以得到相同答案。时间 $O(n \log n+q \log q+n+q)$，存储 $O(n+q)$；离线不一定比逐次二分快，取决于 q 和实际常数。

## 事件扫描中的加入与删除

给每个事件一个生效区间 `[l,r)`，查询时刻 t。按 t 排序，加入 $l\le t$ 的事件，删除 $r\le t$ 的事件，剩余事件恰好满足 $l\le t<r$。可以用堆、多重集合等维护当前需要的统计量。

拓展测试：[AtCoder ABC128 E — Roadwork](https://atcoder.jp/contests/abc128/tasks/abc128_e)。施工位置 x 会将开始时刻 D 的查询条件变为 `[S-x,T-x)`，需要返回有效事件的最小 x，不是本例的元素数量。先证明时间转化，再维护活动集合；相同 x 的多条事件不能用普通集合随意丢弃。

## 使用离线前的检查

- 查询是否独立？执行查询会不会改变数据或影响下一次输入？
- 更新与查询的时间关系能否重排？普通动态操作不能只按阈值排序。
- 相同边界用 `<` 还是 `<=`？半开区间终点必须排除。
- 输出是否通过原 id 恢复？原下标与排序后下标是否混淆？
