## 从规则到程序

1. 确定状态：哪些变量足以决定下一步？位置、方向、时间、资源是否都需要？
2. 确定一次操作：先判条件还是先更新？一个时间点多个事件按什么顺序处理？
3. 确定更新语义：同时读取旧状态，还是后面的操作读取前面更新后的状态？
4. 确定终止：固定轮数、达到目标、无可执行操作，还是检测重复状态？
5. 手算小输入，记录每轮状态，与程序输出比较。

## 完整例子：环上的同步更新

有 n 个位置，值为 0 或 1。每轮每个位置变为“自己与左邻居旧值的异或”。所有位置同时更新，0 的左邻居是 $n-1$。输入 n、轮数 t 和 n 个值，输出 t 轮后的数组。要求 $n\ge 1$、$t\ge 0$，且 n·t 的工作量可接受。

```cpp
#include <bits/stdc++.h>
using namespace std;
const int N = 200005;
int a[N], next_value[N];
int main()
{
    int n, t;
    cin >> n >> t;
    for (int i = 0; i < n; i++)
    {
        cin >> a[i];
    }
    for (int step = 0; step < t; step++)
    {
        for (int i = 0; i < n; i++)
        {
            next_value[i] = a[i] ^ a[(i + n - 1) % n];
        }
        for (int i = 0; i < n; i++)
        {
            a[i] = next_value[i];
        }
    }
    for (int i = 0; i < n; i++)
    {
        if (i > 0)
        {
            cout << ' ';
        }
        cout << a[i];
    }
    cout << '\n';
}
```

正确性：轮开始时 a 保存上一轮全部值；计算 next 时 a 不改变，因此每个位置读取的都是同一轮旧状态。计算完再将 next_value 复制到 a，归纳可知每轮均遵守规则。时间 $O(n\cdot t)$，额外空间 $O(n)$。

手算：[1,0,0] → [1,1,0] → [1,0,1]。若直接从左到右修改 a，第一轮会错误得到 [1,1,1]，因为最后一个位置读到了本轮刚修改的左邻居。$n=1$ 时一轮后为 0；$t=0$ 时输出原数组。

## 事件处理顺序

考虑会议室占用的半开区间 $[\mathrm{start},\mathrm{end})$。同一时刻有人离开、有人进入时，若分别处理事件，应先离开后进入，否则会虚增瞬时人数。若改为闭区间语义，处理规则也要改变。

可以把事件存为 `(time,type)` 排序，其中 type 明确离开/进入的先后；也可以按时间分组，整体更新。排序后处理 $O(n \log n)$，不能遗漏排序成本。不要从“通常离开先处理”推断所有题目都适用，应以题意为准。

## 时间与循环边界

- 时钟是 $0\ldots23$ 小时，跨天时要区分“几点”与“已经过多少小时”。日期题应写独立的闰年、月长函数，先确认使用的历法。
- `i=(i+1)%n` 仅适用于 $n>0$；向前退一步可以写 `(i+n-1)%n`。
- 规则循环不一定很快结束。有限确定性状态重复后将进入周期；是否能跳过整周期取决于输出需求。
- [洛谷 P5723 — 质数口袋](https://www.luogu.com.cn/problem/P5723) 可练习按顺序处理、维护累计量与停止条件。规则模拟分析复杂度时用实际执行步数 T 表示 $O(T)$，不能凭“反复变化”就声称 $O(\log n)$。

## CF2269B — KiaKio and Squared Numbers

[官方题面](https://codeforces.com/problemset/problem/2269/B)。定义 $f(x)$ 为十进制各位数字的平方和，每一轮所有数同时变为 $f(x)$。统计最终能在同一轮相等、并从此始终相等的下标对 $i<j$。$1\le a_i\le10^9$，单组及所有测试的 $n$ 之和均不超过 1000。

> [!tip]- 提示一：相等一次就足够
> 后继完全由当前数值决定。因此只需判断某一轮是否相等；两条轨迹在不同轮经过同一个数，并不能说明它们会同步。

> [!tip]- 提示二：为什么不用无限模拟
> 一次变换后数值至多为 729。考察这 729 个状态的后继与环，确认入环前的最长距离；两条已经入环的轨迹若处于不同位置，以后还能追上吗？

> [!example]- 详细题解
> **源码主线。** `dig(x)` 逐位取出数字并累加平方。外层枚举所有 $i<j$；若原数相等，直接令 `ans` 加一。否则令 `x1=a[j], x2=a[i]`，最多同步变换 20 次，每次先计算两者的新值，相等则计数并结束这一对，否则把新值写回。必须同时前进一步，不能让某一边多走一次。
>
> **从“永远相等”到有限判定。** 若某轮 $x_1=x_2$，之后两边都反复使用相同函数，归纳可知永远相等。反过来，最终永远相等必然包含某个首次相等的时刻。因此源码找到一次相等即可 `break`，同一对不会重复计数。
>
> **20 次的依据。** 小于 $10^9$ 的正数最多九位，所以 $f(x)\le9\times81=729$；唯一十位输入 $10^9$ 直接变成 1。对 $1\ldots729$ 的有限后继表逐点追踪，只有固定点 1 和环 $4\to16\to37\to58\to89\to145\to42\to20\to4$，入环前最多 11 步。例如最长路径之一是 $692\to121\to6\to36\to45\to41\to17\to50\to25\to29\to85\to89$。因此原输入最多 12 步就进入某个环。
>
> **为什么入环后不用继续等。** 第 12 轮时，两者若都到达 1 就已经相等；若进入不同环则永远不同；若在同一个八元环的不同位置，它们每轮移动一格，位置差保持不变，也永远不同。所以所有可能的首次相遇都发生在前 12 轮，源码检查到 20 轮足够。这里用的是整个有限状态表的枚举论证，不能仅凭几个输入变小得快就随意选常数；若改变变换规则，需要重新证明。
>
> **手算与反例。** 对 $(2,20,4)$，第一轮得到 $(4,4,16)$，只有前两个数相等，答案 1。虽然三者最终都在同一个八元环中，但第三个数始终领先一格；按“是否进入同一个环”分组会错算成 3 对。原来就相等的两个 4 则在第 0 轮已经同步。
>
> **实际复杂度。** 每对最多两次 20 轮的数位平方和计算。令初始十进制位数上界为 $D\le10$，首轮之后至多三位，每对耗时 $O(D+20)$，总时间 $O(n^2(D+20))$，在本题范围内记为 $O(n^2)$；数组空间 $O(n)$，单对模拟只用 $O(1)$ 额外空间。$n=1$ 时答案为 0，相同数出现 $c$ 次贡献 $c(c-1)/2$，计数按下标而非按不同数值。
>
> **选读优化。** 也可以把每个数统一模拟到第 12 轮，再按该轮数值统计相等对，避免为不同数对反复计算相同轨迹。它利用的是相同的同步判定，但并非当前源码采用的实现。

## ABC444D Many Repunit Sum

[官方题面](https://atcoder.jp/contests/abc444/tasks/abc444_d)

第i个数是A[i]个1组成的十进制整数，求所有数的精确和；N、A[i]≤2×10⁵。

> [!tip]- 提示一
> 不要构造每个大整数；从低位看，某一位有多少个1？

> [!tip]- 提示二
> 第p位贡献是长度至少p的输入个数，用长度频次的后缀和得到。
>
> 复习：[[01基础算法与思想/03-模拟与实现]]。

> [!example]- 详细题解
> **建模与源码主线。** 源码count先统计各长度，倒序后缀累加；从个位起算v=count[p]+carry，输出位为v%10，carry=v/10，直到超过最大长度且进位为0。result按低位在前保存，最后reverse输出。
>
> **正确性与适用条件。** 每个repunit在1..A[i]位恰贡献1，后缀计数准确聚合所有数字的本位贡献；十进制逐位进位不改变总值。即使超过最大输入长度，carry仍需继续处理，因此不能把循环限死在m位。
>
> **手算与边界。** 长度(1,2,2)对应1+11+11=23，低两位贡献为3和2；长度为1的十个数相加，本位0、进位1，结果10。
>
> **实际复杂度与实现。** 设L=max A[i]，逻辑处理O(N+L+log N)，源码count固定约4×10⁵项初始化也计入开销；空间O(L+log N)有效位数，另有固定计数缓冲。
