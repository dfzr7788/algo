## 从规则到程序

1. 确定状态：哪些变量足以决定下一步？位置、方向、时间、资源是否都需要？
2. 确定一次操作：先判条件还是先更新？一个时间点多个事件按什么顺序处理？
3. 确定更新语义：同时读取旧状态，还是后面的操作读取前面更新后的状态？
4. 确定终止：固定轮数、达到目标、无可执行操作，还是检测重复状态？
5. 手算小输入，记录每轮状态，与程序输出比较。

## 完整例子：环上的同步更新

有 n 个位置，值为 0 或 1。每轮每个位置变为“自己与左邻居旧值的异或”。所有位置同时更新，0 的左邻居是 $n-1$。输入 n、轮数 t 和 n 个值，输出 t 轮后的数组。要求 $n\ge 1$、$t\ge 0$，且 n·t 的工作量可接受。

```cpp
#include <bits/stdc++.h>
using namespace std;
const int N = 200005;
int a[N], next_value[N];
int main()
{
    int n, t;
    cin >> n >> t;
    for (int i = 0; i < n; i++)
        cin >> a[i];
    for (int step = 0; step < t; step++)
    {
        for (int i = 0; i < n; i++)
            next_value[i] = a[i] ^ a[(i + n - 1) % n];
        for (int i = 0; i < n; i++)
            a[i] = next_value[i];
    }
    for (int i = 0; i < n; i++)
    {
        if (i > 0)
            cout << ' ';
        cout << a[i];
    }
    cout << '\n';
}
```

正确性：轮开始时 a 保存上一轮全部值；计算 next 时 a 不改变，因此每个位置读取的都是同一轮旧状态。计算完再将 next_value 复制到 a，归纳可知每轮均遵守规则。时间 $O(n\cdot t)$，额外空间 $O(n)$。

手算：[1,0,0] → [1,1,0] → [1,0,1]。若直接从左到右修改 a，第一轮会错误得到 [1,1,1]，因为最后一个位置读到了本轮刚修改的左邻居。$n=1$ 时一轮后为 0；$t=0$ 时输出原数组。

## 事件处理顺序

考虑会议室占用的半开区间 $[\mathrm{start},end]$。同一时刻有人离开、有人进入时，若分别处理事件，应先离开后进入，否则会虚增瞬时人数。若改为闭区间语义，处理规则也要改变。

可以把事件存为 `(time,type)` 排序，其中 type 明确离开/进入的先后；也可以按时间分组，整体更新。排序后处理 $O(n \log n)$，不能遗漏排序成本。不要从“通常离开先处理”推断所有题目都适用，应以题意为准。

## 时间与循环边界

- 时钟是 $0\ldots23$ 小时，跨天时要区分“几点”与“已经过多少小时”。日期题应写独立的闰年、月长函数，先确认使用的历法。
- `i=(i+1)%n` 仅适用于 $n>0$；向前退一步可以写 `(i+n-1)%n`。
- 规则循环不一定很快结束。有限确定性状态重复后将进入周期；是否能跳过整周期取决于输出需求。
- [洛谷 P5723 — 质数口袋](https://www.luogu.com.cn/problem/P5723) 可练习按顺序处理、维护累计量与停止条件。规则模拟分析复杂度时用实际执行步数 T 表示 $O(T)$，不能凭“反复变化”就声称 $O(\log n)$。
