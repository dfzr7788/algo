## 拓扑序解决什么问题

任务 v 要等所有前置任务完成才能进行，输入 u→v 表示 u 必须先于 v。按编号排序没有意义，因为编号不代表先修关系。暴力枚举排列再验证最坏需要 $n!$ 种，Kahn 算法只关心“还剩多少前驱”。

入度为 0 的点目前不依赖任何未处理点，可以立刻输出；删掉它的出边后，后继入度减少，新的入度零点也能输出。用队列维护这些点，而不是每次全图扫描。

## 手算状态

边 `1→3,2→3,3→4`，入度 `[0,0,2,1]`，初始队列 `[1,2]`。取 1 后 3 入度降为 1，不能进队；取 2 后降为 0，3 进队；再取 3，4 才进队。若加 `4→3`，3、4 最终无法取出，输出数小于 n，说明有环。

## 完整模板

输入有向图 `n m` 和 m 条边，输出一个拓扑序，有环输出 CYCLE。`1<=n<=200000,m<=200000`；有重边就同时按次数增加、减少入度，自环形成环。g 的顺序决定合法序的具体输出，题目若要求字典序最小，用小根堆代替 queue。

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXN = 200000 + 5;
vector<int> g[MAXN];
int indegree[MAXN];

int main()
{
    int n, m;
    cin >> n >> m;
    for (int i = 0; i < m; i++)
    {
        int u, v;
        cin >> u >> v;
        g[u].push_back(v);
        ++indegree[v];
    }
    queue<int> q;
    for (int i = 1; i <= n; i++)
    {
        if (indegree[i] == 0)
        {
            q.push(i);
        }
    }
    vector<int> order;
    while (!q.empty())
    {
        int u = q.front();
        q.pop();
        order.push_back(u);
        for (int v : g[u])
        {
            --indegree[v];
            if (indegree[v] == 0)
            {
                q.push(v);
            }
        }
    }
    if ((int)order.size() != n)
    {
        cout << "CYCLE\n";
        return 0;
    }
    for (int i = 0; i < n; i++)
    {
        cout << order[i] << (i + 1 == n ? '\n' : ' ');
    }
}
```

教学样例输入：

```text
4 3
1 3
2 3
3 4
```

输出：

```text
1 2 3 4
```

## 为什么正确，为什么能判环

输出 u 时它所有未处理前驱数为 0，所以所有先修点已经在前面。若还剩点但无入度零点，从剩余点不断追踪前驱，有限个点中必然重复，产生有向环。反过来环上的每个点始终还有一个环内前驱，不会全部被输出。时间 $O(n+m)$，总空间 $O(n+m)$；字典序最小版本 $O(m+n \log n)$。

## 在拓扑顺序上递推

若问 s 到各点的路径数，初始 $\mathrm{ways}[s]=1$，其他为 0，依序做 `ways[v]+=ways[u]`，按题目模数取模。若问带权 DAG 中 s 到各点的最短路，初始 $\mathrm{dist}[s]=0$、其他 INF，只有有限 $\mathrm{dist}[u]$ 才能松弛出边；DAG 可有负权边，因为不会有环。最长路把 min 改 max，并用 −INF 表示不可达，不可把所有点都初始化为 0，除非题意允许任意起点和空路径。

这里给转移规则而非另一份完整程序：它依赖上面已得到的完整 order，判环成功后才执行。每个状态的全部前驱在它前面，处理时信息已经齐备，所以总递推 $O(n+m)$。不同起点、是否允许空路径、是否统计重边对应不同初始化和计数模型。

## 易错点

Kahn 会修改 indegree；重复调用要恢复。拓扑排序只提供先后约束，不自动统计所有合法排列；一般 DAG 的拓扑序计数远比排序难。若处理了 $k<n$ 个点，不能把已输出前缀当作全图拓扑序。

## ABC456E Endless Holidays

[官方题面](https://atcoder.jp/contests/abc456/tasks/abc456_e)

每座城市有 W 天循环的假日表，从星期第一天的任一假日城市出发，每晚可停留或沿无向道路移动，问能否永远处于假日。

> [!tip]- 提示一
> 城市相同但星期不同，不是同一个决策状态。

> [!tip]- 提示二
> 有限有向状态图中，从允许起点出发的无限行走与可达有向环等价。
>
> 复习：[[04图论/05-拓扑排序与DAG]]。

> [!example]- 详细题解
> **建模与源码主线。** 源码构造的是隐式状态图 `(u,d)`。下一天为 `(d+1)%W`，允许停留或走向邻居，但目标城市在下一天必须标 o。`vis=1` 表示当前递归栈、2 表示已完全处理；DFS 再遇 1 即找到环，再遇 2 无需重算。从所有 `s[i][0]=o` 的状态尝试。
>
> **正确性与适用条件。** 任一无限路线在有限个城市×星期状态中必重复，从而包含可达环；反之先走到环，再重复环即可无限休假。三色 DFS 中只有指向当前栈的边证明有环，指向已完成状态不能据此判环。
>
> **手算与边界。** 只有一座城市、W=2 时，表 oo 可停留两天后回到初始状态；表 ox 则第二天无合法状态。道路不是必走，遗漏停留边会把前者误判。
>
> **实际复杂度与实现。** 状态 O(NW)，考察的隐式边 O((N+M)W)，相应时间 O((N+M)W)，图、表和标记空间 O(M+NW)。源码递归最深可达 NW；大状态图可改显式栈或拓扑删点判环，不能把递归栈视为常数。

## ABC446E Multiple-Free Sequences

[官方题面](https://atcoder.jp/contests/abc446/tasks/abc446_e)

s1=x,s2=y,sn=A·s(n−1)+B·s(n−2)，统计0≤x,y<M中整个无限序列不含M倍数的初值对；M≤1000。

> [!tip]- 提示一
> 只保留相邻两项模M的值，后继唯一。

> [!tip]- 提示二
> 状态(x,y)转到(y,(Ay+Bx) mod M)，触及0为坏，进入无0环则永久安全。
>
> 复习：[[04图论/05-拓扑排序与DAG]]。

> [!example]- 详细题解
> **建模与源码主线。** 源码check用status记结果，1安全、2失败；x=0或y=0立即失败，已知结果直接复用。vis只表示当前调用链；再遇vis状态说明进入未触及0的环，返回安全，并沿调用链缓存。最终遍历非零初值计数。
>
> **正确性与适用条件。** 模运算保留是否为M倍数的信息。有限功能图的轨迹必终止于含0状态或重复成环，两类穷尽；无0环可无限重复，入环的前驱同样安全。每个状态只需确定一次，当前链标记不能混同已完成结果。
>
> **手算与边界。** M=3,A=1,B=0时，非零y让后续一直等于y，所有x,y∈{1,2}共4对安全；y=0必须立即排除。
>
> **实际复杂度与实现。** 状态M²、每态一个后继，时间O(M²)、空间O(M²)。源码递归最深可达M²，存在栈深风险；可用显式路径记录实现同一功能图判环，不能把递归辅助空间漏掉。
