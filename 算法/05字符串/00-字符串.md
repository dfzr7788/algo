## 按需求选方法

| 需求 | 方法 | 条件与区别 |
|---|---|---|
| 小规模找出现位置 | 暴力匹配 | 重叠仍计，最坏 O(nm) |
| 单模式确定性线性匹配 | KMP | pi 的定义与 −1 next 不混用 |
| 多次静态子串比较 | 前缀哈希 | 指纹可能碰撞，先比较长度 |
| 完整单词与前缀数量 | Trie | 路径存在不等于完整词存在 |
| 整串回文 | 双指针 | O(n)，不必 Manacher |
| 小规模最长回文子串 | 中心扩展 | 奇数、偶数都枚举 |
| 长串最长回文子串 | Manacher | 半径与独占 right 按本篇约定 |
| 每个起点与模式匹配多长 | Z / 扩展 KMP | 输出 LCP 而不是 border |
| 多模式分别出现多少次 | AC 自动机 | 重复模式按编号，重叠计数 |
| 整体平移匹配序列前缀 | 差分＋Trie | 分隔符、负号、空差分都处理 |

## 阅读与模板约定

完整程序写清输入范围、字符集、空串、下标、区间、整数类型和数组容量；局部片段明确依赖。除 Trie 的明确多测外，完整程序默认单组。string 使用 0 下标，但 KMP 位置输出、哈希区间有 1 下标合同，不能机械统一成同一数字。

代码四空格缩进、左花括号另起一行、一条语句一行，优先静态数组与具名函数，不为模板包装类。Manacher 的半径随实际字符串长度动态分配，避免固定上限浪费；标准库容器在需要时保留。输入空间与算法辅助空间分别说明，静态容量的实际内存单独估算。

先理解暴力重复了哪些工作，再读优化；线性复杂度的摊还分析放在各篇最后。哈希碰撞、字符集、读取整行、多测初始化、重叠次数、重复词编号等限制不省略。小规模通过暴力对拍只能验证实现，不能证明固定哈希参数对所有输入正确，也不代表平台 AC。
