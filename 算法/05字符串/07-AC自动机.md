## 为什么最后再读这一章

先掌握单串操作、KMP、Trie，已有很多题可以完成。AC 自动机是当前模块中较难的一篇，保留原有主题并补成可用笔记，但学习路线允许先跳过，不添加后缀数组或后缀自动机等新进阶结构。

给大量模式，问它们在同一文本各出现多少次，逐个 KMP 会花 O(模式数×文本长度+模式总长)。Trie 只处理从根开始的前缀，不能每次匹配失败就彻底忘记当前后缀；AC 把“当前可用最长模式前缀”作为状态，配失败指针在一次文本扫描中识别全部词。

## Trie 边、词尾、失败指针分别是什么

一个节点代表一个模式前缀。failure[u] 是该路径字符串的最长**真后缀**中仍为某个模式前缀的节点；它未必是完整单词，也不等同 Trie 父亲。terminal[i] 记录第 i 个模式的终止节点，重复模式会指向同一节点，但仍需按各自编号输出。

go[u][c] 初始是 Trie 的孩子；build 后填补缺边，表示读入 c 后的自动机状态，可能通过 failure 间接跳到另一个前缀。这时 go 不再是一棵树的“真实孩子数组”，不能建完后继续调用原 Trie 插入，否则会误判为已有 Trie 边。插入全部模式→建自动机→扫描，是固定顺序。

## 小例子：he、she、hers、his

she 的 failure 是 he：he 是 she 的后缀，也是一个词前缀；sh 的 failure 是 h：h 不是完整词，但仍是合法前缀。扫描 `ushers`：u 使状态留根，s→s，h→sh，e→she，此时 she 和 failure 上的 he 都在当前位置结束；再读 r，she 没有真实 r 边，沿 he 的 r 边进入 her；再读 s 到 hers。

所以只给当前状态 she 加一次、最后只看 she 自己，最初会漏掉 he。每字符直接沿全部 failure 链逐个累计也可能在 `a,aa,aaa,…` 的模式下扫描大量后缀，不能据此声称线性。

## BFS 建失败指针与补齐转移

根的 failure 仍设根，根的真实孩子 failure=0。按 BFS 逐层取 u，它的 failure 节点更浅、转移已经补齐；真实孩子 v 的失败指针为 go[failure[u]][c]，缺边则 go[u][c]=go[failure[u]][c]。根缺边保留 0。

必须对根孩子单独初始化，不把它们失败指向自己；否则传播或查询会形成错误环。本篇使用数组队列保存 BFS 顺序，同时用于最后反序累计。

## 扫描只计当前状态，最后汇总后缀

scan_text 每读一个字符，用补齐 go 转移并令 visits[u]++。此时 visits 只是“扫描恰好停在这个状态的次数”，不是最终词出现次数。

以所有非根节点的 failure 边构成一棵指向根的树。从 BFS 顺序尾部到头部做 visits[failure[u]]+=visits[u]，把深状态贡献交给它的后缀。终态计数于是包含所有以该词为后缀的扫描位置。

更易手算的模式 `a,aa,aa`，文本 `aaa`：扫描依次停在 a、aa、aa，直接访问为 a=1、aa=2；反序累计后 a=3、aa=2；最后按三个编号输出 3、2、2，重复词不被合并成一个输出。

## 完整模板

输入模式数 n<=200000，n 个非空小写模式，总长度<=200000，再输入非空小写文本，长度<=2×10^6；每个模式的出现次数各一行，允许重叠和重复模式。接口对应 [洛谷 P5357 — AC 自动机](https://www.luogu.com.cn/problem/P5357)。单组程序，全局初始为 0；容量约 24 MB 加文本，不包含空模式。

```cpp
#include <bits/stdc++.h>
using namespace std;

const int MAXNODE = 200000 + 5;
const int MAXPAT = 200000 + 5;
int go[MAXNODE][26], failure[MAXNODE], terminal[MAXPAT], bfs_order[MAXNODE];
long long visits[MAXNODE];
int nodes = 0;

int insert_pattern(const string &pattern)
{
    int u = 0;
    for (char c : pattern)
    {
        int k = c - 'a';
        if (go[u][k] == 0)
        {
            go[u][k] = ++nodes;
        }
        u = go[u][k];
    }
    return u;
}

int build_automaton()
{
    int head = 0;
    int tail = 0;
    for (int k = 0; k < 26; k++)
    {
        if (go[0][k] != 0)
        {
            bfs_order[tail++] = go[0][k];
        }
    }
    while (head < tail)
    {
        int u = bfs_order[head++];
        for (int k = 0; k < 26; k++)
        {
            int v = go[u][k];
            if (v != 0)
            {
                failure[v] = go[failure[u]][k];
                bfs_order[tail++] = v;
            }
            else
            {
                go[u][k] = go[failure[u]][k];
            }
        }
    }
    return tail;
}

void scan_text(const string &text)
{
    int u = 0;
    for (char c : text)
    {
        u = go[u][c - 'a'];
        ++visits[u];
    }
}

void accumulate_failure(int count)
{
    for (int i = count - 1; i >= 0; i--)
    {
        int u = bfs_order[i];
        visits[failure[u]] += visits[u];
    }
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n;
    cin >> n;
    for (int i = 0; i < n; i++)
    {
        string pattern;
        cin >> pattern;
        terminal[i] = insert_pattern(pattern);
    }
    int count = build_automaton();
    string text;
    cin >> text;
    scan_text(text);
    accumulate_failure(count);
    for (int i = 0; i < n; i++)
    {
        cout << visits[terminal[i]] << '\n';
    }
}
```

教学样例输入（自编）：

```text
3
a
aa
aa
aaa
```

输出：

```text
3
2
2
```

## 正确性与复杂度

补齐转移保存已扫描文本后缀中最长的可用模式前缀；failure 枚举其所有仍在 Trie 中的前缀后缀。模式在某个位置结束，当且仅当其末节点出现在当前状态的 failure 链上。反序传播使每次扫描贡献沿这条链到所有祖先，一次且仅一次，因此 visits[terminal[i]] 恰是出现次数。

设模式总长 S、节点 V<=S+1、文本长 N、字符集 σ=26，插入 O(S)、建图 O(σV)、扫描 O(N)、汇总 O(V)、输出 O(n)，总 O(S+σV+N+n)，空间 O(σV+n+N)。固定 σ 时常写 O(S+N+n)，但不能忘记 26 列实际占用。每次查询枚举所有匹配的位置还要计输出规模，不属于本模板仅计数的复杂度。

若有多个文本，先保留 go/failure，**每次清 visits 再扫，再反序汇总**；已汇总 counts 不能在第二次汇总时重复传播。多测重建则还需清 go、failure、terminal、nodes；只清真实树边不够，go 已含补齐边。
