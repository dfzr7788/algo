## 动态规划解决什么问题

许多问题可以枚举所有决策：每件物品选不选、每一步跳到哪里、每个位置放什么。搜索树通常指数增长。若不同决策前缀走到了“后续选择完全相同”的局面，就可以合并这些前缀，只计算一次后续答案。这是动态规划减少重复计算的来源。

状态不是把题面变量抄进数组，而是为剩余问题保留足够的信息。两段历史能合并的条件是：它们未来的合法选择相同，而且历史对目标值的影响能够用当前记录的值表达。例如只能向右跳的青蛙，到达同一石头后，未来只取决于当前位置；已经花了多少费用无需另做维度，只保留到这里的最小费用。

“无后效性”指给定状态后不必再查看被丢弃的历史。它不表示当前与过去无关，也不表示总能只留一维。“最优子结构”指最优解中对应的子问题可以用子问题最优解替换，否则存在更优整体。计数 DP 则合并同状态的方案数，不使用取最优。

## 写转移前的六个问题

1. `dp[...]` 精确表示哪个集合的答案？是恰好、至多、以某点结尾，还是某个子树？
2. 最后一步有几种互斥且穷尽的选择？计数题尤其不能重复。
3. 这些选择依赖哪些子状态？子状态是否严格更小？
4. 空状态、起点、不可达状态分别是什么？
5. 答案在一个状态里，还是需要对一组终点取最大或求和？
6. 状态数乘每个状态的转移成本是多少？空间能否承受？

最大化不可达通常用负无穷，最小化用正无穷；计数不可达用 0，空方案用 1。不能把“值是 0”和“没算过”混在一起，记忆化搜索需独立访问标记。

## 从递归到记忆化，再到递推

青蛙从 1 跳到 n，每次前进 1 或 2，跳跃费用为两块石头高度差绝对值。枚举所有跳法的递归有大量相同后缀。定义 `solve(i)` 为从 i 到 n 的最小费用：终点费用为 0，其余比较跳到 $i+1$ 和 $i+2$ 的费用加后缀答案。

高度 `10 30 40 20`：`solve(4)=0`；`solve(3)=20`；`solve(2)=min(10+20,10+0)=10`；`solve(1)=min(20+10,30+20)=30`。同一个 `solve(3)` 无论从哪里到来都一样，缓存它不会丢失更优答案。

下面是完整教学程序，单组，1 下标，`1<=n<=5000`、`|h[i]|<=10^9`，输出最小费用。容量 $\mathrm{MAXN}=5005$；费用用 long long，递归深度最多 n。5000 的递归仍依赖运行环境栈空间，大规模优先用下篇的循环递推。官方 [AtCoder DP A — Frog 1](https://atcoder.jp/contests/dp/tasks/dp_a) 可到 $10^{5}$，本教学递归版不能直接据此保证栈安全。

```cpp
#include <bits/stdc++.h>
using namespace std;
const int MAXN = 5000 + 5;
int n;
long long h[MAXN];
long long memo[MAXN];
bool visited[MAXN];

long long solve(int i)
{
    if (i == n)
    {
        return 0;
    }
    if (visited[i])
    {
        return memo[i];
    }
    visited[i] = true;
    long long answer = llabs(h[i] - h[i + 1]) + solve(i + 1);
    if (i + 2 <= n)
    {
        answer = min(answer, llabs(h[i] - h[i + 2]) + solve(i + 2));
    }
    memo[i] = answer;
    return answer;
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n;
    for (int i = 1; i <= n; i++)
    {
        cin >> h[i];
    }
    cout << solve(1) << '\n';
}
```

教学输入（自设，非官方样例）：

```text
4
10 30 40 20
```

输出：

```text
30
```

## 正确性与复杂度

对剩余距离归纳：合法第一跳只有两种，之后的问题正是对应后缀；费用可加，取最小即可。每个状态只展开一次，时间 $O(n)$，缓存 $O(n)$，递归栈 $O(n)$。无记忆化的递归满足斐波那契式调用数，指数增长。

循环递推是在同一状态依赖图上按拓扑顺序填表。向后求费用时从 n 到 1；向前求到达费用时从 1 到 n。不能只是把递归函数换成任意循环。一般有环依赖不能直接套这套 DP，可能需要最短路、方程或重新增加阶段。

## CF2173B Niko's Tactical Cards

[官方题面](https://codeforces.com/contest/2173/problem/B)

初始分数0，每回合必须选k←k−a[i]或k←b[i]−k，求最终最大分数；a、b可为负。

> [!tip]- 提示一
> 第二种操作反转大小关系，只记录最大值会丢失潜力。

> [!tip]- 提示二
> 同时保存实际可达最小mn、最大mx，用旧端点一起计算新端点。
>
> 复习：[[08动态规划/01-状态设计与记忆化搜索]]。

> [!example]- 详细题解
> **建模与源码主线。** 源码newmx=max(mx−a[i],b[i]−mn)，newmn=min(mn−a[i],b[i]−mx)，计算完才写回。第一种仿射变换单调递增，第二种单调递减，所以每个分支的极值只取决于旧集合的两端，无需枚举指数多个方案。
>
> **正确性与适用条件。** 不变量是可达集合的准确最小、最大元素，不要求中间整数全部可达。仿射映射的极值在端点取得，且端点确实可达；两个分支取并集后极值由四个候选完全确定，归纳成立。
>
> **手算与边界。** 首轮a=5,b=2，端点为−5、2；次轮b=10，翻转从旧最小−5得到15，优于仅保留旧最大2所得到的8。
>
> **实际复杂度与实现。** 时间O(N)，源码两数组空间O(N)，状态O(1)。必须先求两个new值再覆盖，不能混用新旧端点；累计分数可达N·10⁹量级，使用long long。

## CF2208C Stamina and Tasks

[官方题面](https://codeforces.com/contest/2208/problem/C)

按顺序选任务，初始体力S=1，做i获S·c[i]后体力乘(1−p[i]/100)，也可跳过，求最大得分。N≤10⁵。

> [!tip]- 提示一
> 起始体力乘S会让任意后续方案的收益整体乘S。

> [!tip]- 提示二
> 逆序维护单位体力的最优后缀价值，比较做与不做。
>
> 复习：[[08动态规划/01-状态设计与记忆化搜索]]。

> [!example]- 详细题解
> **建模与源码主线。** 源码先把百分数p除以100，倒序更新ans=max(ans,c[i]+(1−p[i])·ans)。旧ans是后缀i+1在单位体力下的最优收益；做当前题先得c，再把后续最优收益按剩余体力缩放。p是确定的衰减比例，这里没有成功概率或随机事件。
>
> **正确性与适用条件。** 任意固定后续方案的收益均正比于起始体力，全部方案取最大后仍有这一正齐次性。当前两分支穷尽所有决策，而后续均可取相应最优解，因此倒序归纳正确，状态不必记录连续的体力数值。
>
> **手算与边界。** 任务(10,5),(10,80),(20,5)：末尾ans=20，中间做只能得14故跳过，最前做得到10+0.95×20=29。
>
> **实际复杂度与实现。** 时间O(N)，源码c、p数组O(N)，DP状态O(1)。用long double并按误差要求输出。p=0的正收益任务应做；p=100会清空未来体力，但当前收益仍可获得。
