前置：[[01-博弈基础与必胜必败态]]。巴什博弈（Bash Game）处理一堆 n 个物品，每次取 1..m 个、取到最后者获胜的问题，要求 m≥1 且固定。

## 为什么需要模规律

逐个递推 win[0..n] 至少要遍历 n 个状态，n 达到 10^18 时不可行。连续的取数范围让我们能找到一组间隔相同的必败态，直接用余数判断并给出第一步。

**巴什博弈：难度 2/10，重要程度 7/10**，适合练习必败集合证明。**反常巴什：难度 3/10，重要程度 5/10**，需要改变终局与边界。

## 从小状态推导公式

0 无法行动，是 P 态。1..m 都可一次取完，是 N 态。m+1 无论取多少，都给对手留下 1..m，因此是 P 态。接着 m+2..2m+1 都能取掉余数，回到 m+1。

猜想并证明所有 P 态恰为 m+1 的倍数：

1. 终局 0 属于集合。
2. 从倍数取 1..m，不可能到另一倍数。
3. 非倍数 n 的余数 r=n mod (m+1) 位于 1..m，取 r 后到达倍数。

由于每次数量严格减少，这三个条件和状态归纳一起完成证明。

$$
\text{先手必胜}\iff n\bmod(m+1)\ne0.
$$

## 手算和回应策略

原例 n=10、m=3：先取 2，留 8。对手取 1，自己取 3，留 4；对手取 3，自己取 1，取完获胜。对手每次取 x，自己回应 m+1−x，每两步共取 m+1。

回应确实合法：轮到对手时正数剩余是某个正倍数，至少 m+1；他取 x 后至少剩 m+1−x。若初始就是倍数，后手使用同样的配对策略。

## 完整程序：胜负与首步

自编教学格式：第一行 T；每组 n、m，0≤n≤10^18，1≤m≤10^18。必败输出 `Second`；必胜输出 `First r`，r 是应取数量。使用 long long；m+1≤10^18+1 不会溢出。n=0 表示初始就轮到一个无法行动的人。

```cpp
#include <iostream>
using namespace std;

long long winning_take(long long n, long long m)
{
    return n % (m + 1);
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int t;
    cin >> t;
    while (t--)
    {
        long long n, m;
        cin >> n >> m;
        long long take = winning_take(n, m);
        if (take == 0)
        {
            cout << "Second\n";
        }
        else
        {
            cout << "First " << take << '\n';
        }
    }
    return 0;
}
```

样例：输入三组 `(10,3)`、`(8,3)`、`(0,3)`，第一行写 3，分别输出 `First 2`、`Second`、`Second`。每组 O(1) 时间和 O(1) 空间。

## 反常规则：取走最后一个者输

现在限定初始 n≥1，仍每次取 1..m。n=1 时唯一行动直接输，是 P 态；当 2≤n≤m+1 时取 n−1 留 1，是 N 态。不能说“n≤m 时都能取 n−1 必胜”，因为 n=1 时这样会取 0，违法。

正数 P 态恰为：

$$
n\equiv1\pmod{m+1}.
$$

非 P 态取 `(n−1) mod (m+1)`，留下同余 1 的正数；P 态任何未取完的合法动作都走到 N 态，取完则立即输。之后配对维持同余 1，最终让对手面对 1。把输赢直接绑定到最后一次操作时，不要无解释地给初始空堆套 `(n−1)` 公式。

判断可用 `n % (m+1) != 1`，前提 n≥1。这是局部表达式，若需程序把上面判定和首步一起改写，不能只改变输出名称。

## 与 SG、练习及常见错误

正常规则单堆 SG(n)=n mod (m+1)，所以多个独立巴什堆要异或各堆余数，不能对总石子数取模，见 [[04-SG函数与SG定理]]。允许取的集合若有缺口，例如 {2,3}，不能把最大取数 3 当成巴什参数。

练习见 [[11-博弈题单]] 的 B1、B2 与 DP K 连续集合变式；先手算 m=1、n=0、n≤m、n=m+1，再验证反常规则的 n=1、2。
