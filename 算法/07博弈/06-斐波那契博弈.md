前置：[[01-博弈基础与必胜必败态]]。斐波那契博弈（Fibonacci Nim）中，取数上限依赖上一次行动，不能像巴什那样只看一个固定 m。

## 规则、用途与暴力状态

初始一堆 n≥2 颗石子。首步取 1..n−1，不能全部取完；此后若上一步取了 t，当前可取 1..min(n,2t)，取最后者赢。

只判断初始胜负时有斐波那契判定；若要在中途选择必胜操作，还要看上限。暴力状态应为 (剩余 n,当前最多可取 r)，转移到 (n−t,2t)。只记 n 会把未来动作不同的局面错误合并。n=1 若沿用“首步不能取完”也无合法首步，但主模板限定 n≥2。

**难度 6/10，重要程度 4/10**：专用动态上限模型，适合选学数论分解与状态分析。

## 初始结论与分解

采用不重复的数列 F1=1、F2=2、Fi=F(i−1)+F(i−2)，即 1、2、3、5、8、13、21……。初始先手必败当且仅当 n 是这个数列中的项。

齐肯多夫定理：每个正整数唯一表示成若干个互不相邻的斐波那契项之和。例如 11=8+3，12=8+3+1，19=13+5+1。可从大到小贪心取不超过剩余数的最大项；取 Fi 后余数小于 F(i−1)，所以不会再取相邻项。

设 z(n) 是这个分解中的最小项。一般中途状态 (n,r)，n>0：

$$
(n,r)\text{ 必胜}\iff r\ge z(n).
$$

必胜时取走 z(n)。初始 r=n−1；若 n 是斐波那契数，z(n)=n>r；否则分解至少两项，z(n)<n，首步合法。

这个一般状态判定和相关引理可参见 [Larsson 与 Rubinstein-Salzedo — Global Fibonacci Nim，§5 与 Lemma 12](https://arxiv.org/html/1509.08527)。此处只使用其中单堆结论。

## 手算与不变量

原例 n=11=8+3，先取 3，剩 8，对手上限 6，不能取 z(8)=8。若对手取 1，剩 7=5+2，自己上限 2，取 z(7)=2，剩 5，对手上限 4；若对手再取 2，剩 3，自己上限 4，直接取完赢。

n=8 时首步上限 7，z(8)=8，必败。例如先手取 3，剩 5、上限 6，后手可直接取完。仅举这条路线不能证明所有首步都输，证明要覆盖所有 t。

## 正确性要点

若 r≥z(n)=Fi，取 Fi；若没有剩余则获胜，否则剩余分解最小项至少为 F(i+2)，并且 F(i+2)>2Fi，因此交给对手的上限 2Fi 小于新最小项。

若 r<z(n)，任何合法 t 都满足 t<z(n)。使用分解引理 `z(n−t)≤2t`，说明对手在新局面总有上述合法必胜取法。结合 n 严格下降，对两类状态归纳便得到完整判定。

原笔记里的 `2Fi<F(i+1)` 不成立，例如 2×3>5；应使用下标至少相差 2 得到 `2Fi<F(i+2)`。分解中的数项只是分析工具，不能把它们直接当成可独立行动的多堆游戏做 SG 异或。

## 完整程序：初始判胜并构造首步

自编教学格式：第一行 T，每组一个 n，2≤n≤10^18。败输出 `Second`；赢输出 `First t`，t 为最小分解项。与旧模板“读到 0 结束、输出 First win/Second win”不同；旧模板不是已核验的平台格式，本篇统一说明输入契约。

fib 数组 0 下标、容量 100，存到≤10^18 的最后一项。加法前用 `a <= LIMIT−b` 判断，不生成越界项。`smallest_term` 从大到小分解，最后使用的项就是最小项；没有把石子真实拆成多堆。

```cpp
#include <iostream>
using namespace std;

const long long LIMIT = 1000000000000000000LL;
long long fib[100];
int count_fib;

void build_fib()
{
    fib[0] = 1;
    fib[1] = 2;
    count_fib = 2;
    while (fib[count_fib - 2] <= LIMIT - fib[count_fib - 1])
    {
        fib[count_fib] = fib[count_fib - 1] + fib[count_fib - 2];
        count_fib++;
    }
}

long long smallest_term(long long n)
{
    long long answer = 0;
    for (int i = count_fib - 1; i >= 0; i--)
    {
        if (fib[i] <= n)
        {
            n -= fib[i];
            answer = fib[i];
        }
    }
    return answer;
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    build_fib();
    int t;
    cin >> t;
    while (t--)
    {
        long long n;
        cin >> n;
        long long take = smallest_term(n);
        if (take == n)
        {
            cout << "Second\n";
        }
        else
        {
            cout << "First " << take << '\n';
        }
    }
    return 0;
}
```

样例四组 n 为 2、8、11、12，分别输出 Second、Second、First 3、First 1。预处理 O(log LIMIT)；每组扫描 O(log LIMIT)，有效存储 O(log LIMIT)，固定数组分配 100 项。

## 边界、变式与扩展选读

首步如果允许取完，所有正数初始都可以一步获胜，原结论立即失效。中途不能仅判断 n 是否 Fibonacci：剩 8、上限 8 可直接赢；剩 11、上限 2 则因 z(11)=3 而败。

进阶引理 `1≤t<z(n) ⇒ z(n−t)≤2t` 涉及斐波那契借位分解，本篇将它明确作为引用的数学引理，不用几行直觉冒充其完整证明。一般判定的双向证明已在正文说明。可用 [[12-博弈综合练习]] 的完整状态暴力，在小 n 枚举所有上限验证，而不是只检测“是否是 Fibonacci”。多堆若共享上一手取数上限，子游戏不独立，不能直接异或各堆结果。
