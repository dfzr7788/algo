## 题目与目标

[AtCoder ABC368 F — Dividing Game](https://atcoder.jp/contests/abc368/tasks/abc368_f)：每次选择一个数，用它的任意正真因数替换；无法操作者输。N≤100000，初始数在 2..100000，Anna 先手，输出 Anna 或 Bruno。

**因数游戏 SG 优化：难度 6/10，重要程度 7/10**：训练从操作集合推导可合并的价值，而不是先猜一个看起来像 Nim 的数值。

## 第一步：确定独立游戏与终局

一个数 x 是一个子游戏。一次只改一个数，不影响其他数的动作，满足独立和。x=1 无真因数，是终局，SG(1)=0；每次替换成更小数，所以游戏有限。

直接递推为：

$$
SG(x)=\operatorname{mex}\{SG(d):d\mid x,\ 1\le d<x\}.
$$

小规模可对每个 x 枚举 d 或成对因数，但扫到 sqrt(x) 再取 mex，预处理到 M 的直接方法可达到 O(M sqrt M) 量级。若对每个局面展开完整多数组游戏树，重复和组合状态更多；独立和已避免了这个瓶颈。

## 第二步：找影响因数的真实量

写 x=p1^e1·...·pk^ek，定义 Ω(x)=e1+...+ek，即**计重数的质因子个数**。真因数的每个指数只能减少，总个数可从 0 到 Ω(x)−1。

反过来，每个整数 j∈[0,Ω(x)−1] 都可达到：把 x 的质因子按重数列出，选其中任意 j 个相乘，得到一个真因数，Ω 恰为 j。因此后继的 Ω 值集合恰为整个连续区间。

归纳假设所有真因数 d 都满足 SG(d)=Ω(d)，于是后继 SG 集合为 0..Ω(x)−1，mex 正好为 Ω(x)。终局 1 满足 Ω(1)=0，所以：

$$
SG(x)=\Omega(x),\qquad \text{Anna 获胜}\iff\bigoplus_i\Omega(A_i)\ne0.
$$

不能改成“不重复的质因子种数”：4=2² 有两个质因子，能变 1 或 2，SG(4)=mex({0,1})=2，而不是 1。也不能对原始 A[i] 异或。

## 手算

12=2²·3，Ω(12)=3；它的真因数 1、2、3、4、6 的 Ω 为 0、1、1、2、2，mex 为 3。初始 (2,3,4) 的 SG 为 (1,1,2)，总异或 2，Anna 赢，可将 4 换成 1，使总异或归零。

注意题面给出一条游戏过程并不意味着它是最优过程；最终答案应来自双方最优的证明。

## 第三步：预处理最小质因子

`build_spf` 为每个数保存最小质因子。按质数 p 递增，给尚未标记的倍数设置 p；p² 之前的合数已被更小质数覆盖。质数本身记录 spf[p]=p。

随后递推 `omega[x]=omega[x/spf[x]]+1`，右边严格更小，按 x 升序求值即可。避免对每个输入重新分解。与线性筛不同，这里是普通最小质因子筛，不宣称线性总复杂度。

## 完整程序

输入输出使用上述官方题目格式。A 为 1..100000 的值域；数组以数值为下标，索引 1 终局；初始题目不含 1，但递推必须保留 omega[1]=0。数组全局初始化为零，程序处理一组数据。

```cpp
#include <iostream>
using namespace std;

const int MAXA = 100000;
int spf[MAXA + 1];
int omega[MAXA + 1];

void build_spf()
{
    for (int p = 2; p <= MAXA; p++)
    {
        if (spf[p] != 0)
        {
            continue;
        }
        spf[p] = p;
        if (1LL * p * p <= MAXA)
        {
            for (int x = p * p; x <= MAXA; x += p)
            {
                if (spf[x] == 0)
                {
                    spf[x] = p;
                }
            }
        }
    }
    omega[1] = 0;
    for (int x = 2; x <= MAXA; x++)
    {
        omega[x] = omega[x / spf[x]] + 1;
    }
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    build_spf();
    int n;
    cin >> n;
    int sum = 0;
    for (int i = 0; i < n; i++)
    {
        int x;
        cin >> x;
        sum ^= omega[x];
    }
    cout << (sum != 0 ? "Anna" : "Bruno") << '\n';
    return 0;
}
```

输入 `3`，第二行 `2 3 4`，输出 Anna；输入 `4`，第二行 `2 3 4 6`，输出 Bruno。筛的时间 O(M log log M)，omega 递推 O(M)，读入 O(N)，总空间 O(M)，M=100000。

## 从这个题解学到的方法

真正的简化来自“每个更小的候选价值都能达到、没有其他候选价值”，不是只证明某个量每步减少。若规则改成“只能除去一个质因子”，每一步 Ω 恰少 1，SG 会变成 Ω mod 2，原公式就不能用。

构造首步时需先找目标 SG，再选合法因数。比如 Ω(x)=k，需要变到 j<k，可选 j 个计重质因子的乘积；判断模板没有保存这些质因子，不能直接把 k−j 当成要减去的数值。

练习先独立重做 ABC368 F，再完成 [[12-博弈综合练习]] 的规则改动题。小规模验证应枚举所有真因数计算 mex，与筛出的 omega 比较，避免用同一个质因子公式同时当实现和答案。

## 第二例：牛客 Rock-Paper-Scissors String Game

题目：[牛客竞赛 141374 E — Rock-Paper-Scissors String Game](https://ac.nowcoder.com/acm/contest/141374/E)。本题题面、范围与样例依据用户提供的官方页面截图核对；此前无法读取网页的缺口已由截图补齐。

**字符串删除博弈与终局构造：难度 4/10，重要程度 6/10**。本题适合学习“先证明能一步交出终局，再把胜负简化为是否存在动作”，这一结论不能推广到任意博弈。

### 规则与朴素方法

字符串只包含 R（石头）、P（布）、S（剪刀），克制关系为 R 胜 S、S 胜 P、P 胜 R。Alice 先手，双方轮流选择长度至少为 2 的连续子串 s[l..r]，要求 **l<r 且 s[l] 战胜 s[r]**，随后删除整个闭区间，剩余前后两段按原顺序拼接。不能操作的人输。

第一行 T，1≤T≤10000；每组输入 n 与长度为 n 的字符串，1≤n≤1000000，所有测试的 n 之和≤1000000。输出 Alice 或 Bob。

这里端点不要求相邻，操作对象却必须是连续子串，删除时也包括端点。枚举全部区间已有 O(n²) 个候选；再递归枚举剩余字符串会产生大量状态，不适用于百万长度。只看最后一对字符、相邻字符或各类字符出现次数，都可能丢失关键顺序信息。

### 核心结论：有合法动作就能一步获胜

没有合法动作时，Alice 立即输。有合法动作时，存在一次删除，使剩余字符串没有任何合法动作，Bob 立即输。因此答案等价于：

$$
\exists\,l<r,\ s_l\text{ 战胜 }s_r\quad\Longleftrightarrow\quad\text{Alice 获胜}.
$$

下面证明关键的“存在一步到终局”。不能只从“有动作”直接断言必胜。

### 先认识哪些字符串是终局

空串、同一种字符组成的串都无法操作。如果只有两种字符 W、L，且 W 战胜 L，那么没有合法动作当且仅当所有 L 都在所有 W 之前，即 `L*W*`（星号表示重复零次或多次）。一旦有 W 出现在 L 前面，就可以选这两个位置作为端点。

出现全部三种字符的字符串一定有动作：选三种字符各一个，按位置排列为 X、Y、Z；如果 X 不胜 Y、Y 不胜 Z，则循环克制关系必使 X 胜 Z。至少存在一对合法端点。

所以非空终局恰为 `R*P*`、`P*S*`、`S*R*` 中的字符串；单字符串也包含在这些形式中。这里描述的是字符次序，不是计数奇偶。

### 两种字符：删除从第一个胜者到最后一个败者

若字符串恰有 W、L 两种字符，W 战胜 L，且存在合法动作，那么第一个 W 一定在最后一个 L 之前。删掉这两点之间的整段，前缀只有 L、后缀只有 W，得到终局 `L*W*`。

若第一个 W 已在最后一个 L 之后，原串本来就是终局，应输出 Bob。不能为了套构造而选择 l≥r。

### 三种字符：四种情况覆盖所有排列

令 A=s[1]，B 为从左到右遇到的第一个不同于 A 的字符，C 为第三种字符。令 f_B 为 B 的首次位置，p_A、p_B、p_C 为各字符最后一次出现的位置，均使用题面 1 下标。位置 f_B 之前只包含 A。

三种字符都存在，A、B 之间只有两个可能的克制方向：

| 克制方向 | 末次位置关系 | 删除区间 | 剩余字符串 |
|---|---|---|---|
| A 胜 B，因此 B 胜 C | p_B>p_C | [1,p_B] | 只包含 A |
| A 胜 B，因此 B 胜 C | p_C>p_B | [f_B,p_C] | 只包含 A |
| B 胜 A，因此 A 胜 C | p_A>p_C | [f_B,p_A] | `A*B*`，A 不胜 B |
| B 胜 A，因此 A 胜 C | p_C>p_A | [1,p_C] | 只包含 B |

不同字符的末次位置不可能相等，所以表格覆盖全部情况。逐行验证：

1. 第一行端点为 A、B，合法；最后一个 B 比最后一个 C 更靠后，删除后两者都消失，剩余只能是 A。
2. 第二行端点为 B、C，合法；f_B 前只有 A，p_C 后既没有 B 也没有 C，所以两段拼起来仍只有 A。
3. 第三行端点为 B、A，合法。因为 C 首次出现晚于 f_B，且 p_A>p_C，所以 p_A>f_B，区间长度至少为 2。前缀只有 A，后缀既没有 A 也没有 C，只能是 B，得到没有动作的 `A*B*`。
4. 第四行端点为 A、C，合法；p_C 后既无 A 也无 C，剩余只能是 B。

由此，每个三种字符都出现的状态能一步到终局；结合两种字符和单字符情况，证明了所有非终局都是必胜态。证明用到了三种字符的循环克制结构以及“可删掉任意合法端点间整段”的规则。

### 从构造证明到 O(n) 判定

题目只要求赢家，无需实现上表中的操作构造。扫描当前字符之前，维护前缀是否出现过 R、P、S：

- 当前为 S，之前有 R，则找到 R 胜 S。
- 当前为 P，之前有 S，则找到 S 胜 P。
- 当前为 R，之前有 P，则找到 P 胜 R。

一旦找到就返回 Alice；扫完都未找到就返回 Bob。先检查、后将当前字符加入 seen，保证左端点严格在当前右端点之前。若找到的是相隔很远的两字符，仍是合法子串的两端，不需要它们相邻。

### 完整 C++17 程序

程序按上述官方截图中的格式读入多组数据。`first_wins` 的职责是检测有序克制对；seen 为 3 个布尔值，每组函数调用重新初始化。C++ 字符串使用 0 下标，与证明中的题面 1 下标仅差一位；算法无需输出端点。

```cpp
#include <iostream>
#include <string>
using namespace std;

int symbol_id(char ch)
{
    if (ch == 'R')
    {
        return 0;
    }
    if (ch == 'P')
    {
        return 1;
    }
    return 2;
}

bool first_wins(const string &s)
{
    bool seen[3] = {false, false, false};
    for (char ch : s)
    {
        int current = symbol_id(ch);
        int winner = (current + 1) % 3;
        if (seen[winner])
        {
            return true;
        }
        seen[current] = true;
    }
    return false;
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int t;
    cin >> t;
    while (t--)
    {
        int n;
        string s;
        cin >> n >> s;
        cout << (first_wins(s) ? "Alice" : "Bob") << '\n';
    }
    return 0;
}
```

编号为 R=0、P=1、S=2；能战胜 current 的字符编号恰为 `(current+1)%3`。题面保证 s 仅包含这三种字符且 s.size()=n，程序不需要另做输入合法性处理。

### 官方截图样例与手算

输入：

```text
6
3
RPP
2
RS
4
RPSS
1
P
5
RRRRR
10
RPPRSSPSRP
```

输出：

```text
Bob
Alice
Alice
Bob
Bob
Alice
```

RPP 中 R 不能战胜后面的 P，两个 P 也不能互相战胜，Bob 赢。RS 可全删，Bob 面对空串。RPSS 中端点 R、S 可以取全串，也可按题面说明删除 [1,3] 的 RPS，留下单字符 S，均立即获胜。

最后一组可选择 [6,10]：s[6]=S、s[10]=P，S 战胜 P，删除后剩 `RPPRS`，这并非终局，不能用这次操作作为必胜证明。用上表选择 A=R、B=P、C=S；B 胜 A，p_R=9>p_S=8，应删 [2,9]，留下 `RP`，对手无法行动。这也说明“存在合法动作就能赢”不等于“随便删一个合法区间都能赢”。

### 复杂度、边界和反例

每组最坏 O(n) 时间，全部数据 O(Σn)。判定函数只用 O(1) 额外空间；完整程序读入字符串，存储为 O(n)，不能把整个程序空间笼统写成 O(1)。

- n=1 或全同字符：没有合法动作，Bob。
- RP 与 PR 字符计数相同，前者 Bob、后者 Alice，顺序不可忽略。
- RPS 相邻的 RP、PS 都不能操作，但端点 R 胜 S，可以删除全串，Alice；因此不能只查相邻字符。
- RSRS 删前两个字符后留下 RS，对手会全删；正确策略可直接全删。能动必胜是“存在策略”，不是每个合法动作都获胜。
- 每组 seen 必须重置；不能使用上一组出现过的字符判断当前串。

### 验证与复习

用真实游戏规则枚举所有 l<r 且左端点战胜右端点的区间，删除并拼接，再记忆化判断“是否存在一个必败后继”。这个暴力模型不使用“能动必胜”的结论，可以独立核对扫描程序和上表构造。
