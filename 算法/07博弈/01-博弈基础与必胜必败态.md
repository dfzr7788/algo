## 用途与模型条件

例如还剩 7 颗石子，每次只能取 2 或 3 颗。枚举一条行走路线只能说明双方可能怎样玩；判断必胜必须考虑对手的所有回应。完整游戏树会重复出现“剩同样多石子”的子问题，保存状态结果可以避免重复搜索。

本篇默认两人轮流、信息完全、无随机，所有操作序列有限，不能行动者输，称为正常规则。无偏表示同一完整状态下，两位玩家可选的操作相同；这比“每人轮流一次”更强。有限状态并不保证游戏有限：有环可能永远走下去。

## P 态和 N 态始终相对于当前行动者

- P 态：当前行动者必败，对方在最优策略下获胜。
- N 态：当前行动者存在必胜策略。
- 正常规则的终局没有合法操作，是 P 态。
- 能走到至少一个 P 态，就是 N 态。
- 所有合法操作都走到 N 态，就是 P 态。

不能把 `win[x]` 理解成“初始先手到达 x 就赢”。一次操作后轮到对手，同一个布尔值已经换了评价对象。用数学表达式写：

$$
win(x)=\bigvee_{x\to y}\neg win(y).
$$

空后继集合的逻辑或为假。正确性可以按“距离终局的最大步数”归纳：已知后继胜负后，有一个对手必败的选择即可获胜；没有这样的选择，无论怎样行动都会给对手必胜局面。

## 怎样定义完整状态

状态必须保存决定未来操作和收益的全部信息。固定集合取石子只需剩余数 x；斐波那契博弈还需当前上限 r；有一次特殊行动的规则还需记录权限是否用过；两人的可选动作不同，通常要记录轮到谁。

若两个历史合并后未来合法动作不同，状态就不完整。将“总石子数”作为多堆 Nim 状态也会丢失信息：两堆 $(1,1)$ 和单堆 (2) 总数相同，胜负却不同。

## 手算：每次取 2 或 3

| 剩余 x | 可到达状态 | $win[x]$ | 原因 |
|---:|---|---|---|
| 0 | 无 | P | 无法行动 |
| 1 | 无 | P | 有石子也不一定能动 |
| 2 | 0 | N | 取 2 |
| 3 | 1、0 | N | 两种都能交出 P 态 |
| 4 | 2、1 | N | 取 3 留 1 |
| 5 | 3、2 | P | 两个后继都为 N |
| 6 | 4、3 | P | 两个后继都为 N |
| 7 | 5、4 | N | 取 2 留 5 |

重点是 1 也是终局，而 5 虽然能动却必败。“能动就赢”必须有额外的规则证明。

## 完整程序：集合取数的胜负 DP

对应 [AtCoder DP K — Stones](https://atcoder.jp/contests/dp/tasks/dp_k)。输入 N、K，再输入 N 个严格递增的正整数取数；$N\le 100$，$K\le 100000$，输出 First/Second。数组 move_size 为 0 下标，win 保存 $0\ldots K$。这里不要求取到空堆，只要求对手无合法动作。

```cpp
#include <iostream>
using namespace std;

const int MAXK = 100000 + 5;
const int MAXN = 100 + 5;
int move_size[MAXN];
bool win[MAXK];

void build_win(int n, int k)
{
    win[0] = false;
    for (int x = 1; x <= k; x++)
    {
        win[x] = false;
        for (int i = 0; i < n; i++)
        {
            if (move_size[i] <= x && !win[x - move_size[i]])
            {
                win[x] = true;
                break;
            }
        }
    }
}

int main()
{
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int n, k;
    cin >> n >> k;
    for (int i = 0; i < n; i++)
    {
        cin >> move_size[i];
    }
    build_win(n, k);
    cout << (win[k] ? "First" : "Second") << '\n';
    return 0;
}
```

教学样例输入 `2 7`，第二行 `2 3`，输出 `First`；把 K 改为 5 输出 `Second`。规模较大时不能对每条路线递归展开，递推时间 $O(NK)$、有效状态空间 $O(K+N)$，静态分配按声明容量计算。

## 从数轴到状态图

这里每次 x 严格减少，所以按 x 从小到大求即可。一般 DAG 可逆拓扑序求值；记忆化 DFS 也行，但要确认无环且递归深度可承受。已经算出的结果与“正在访问”的标记不能混用。

图上可能有平局时，不能用“遇到环就返回必败”。需要按具体规则分析胜、负、平，或者证明所有可达状态都会结束。计分游戏则参考 [[08-得分博弈与区间DP]]。
